# English translation guide (영어판 번역 규칙)

The English site (`en/`) is generated by `tools/i18n_en.py` from the Korean site.
This guide is for whoever translates (people or agents). Read it fully before translating.

## Who the reader is

English-speaking Christians who want to study the Bible with the lectures of
**Pastor Woo-ho Noh (노우호 목사)** of **Ezra House (에스라하우스)**. Many are not experts.
Write clear, natural, warm English. Keep the speaker's voice: the lecture notes are
spoken Korean (casual, direct, sometimes humorous). Don't make it stiff, don't add
explanations, don't drop content. Translate everything that is there.

## Two kinds of work

### A. Sentence files (`i18n/work/NNN-*.ko.json` → `NNN-*.en.json`)

`*.ko.json` = `{"source": "js/app.js", "items": [["1", "한국어 문장", 202], ...]}`
(id, Korean text, line number in the source file — open the source file at that line when
a short phrase needs context).

Write `*.en.json` next to it: `{"1": "English text", "2": "...", ...}` — one entry for **every** id.
Then run `python tools/i18n_en.py check NNN-name` (from the `bible/` folder) and fix every problem until it says ok.

Rules that the checker enforces (the site breaks otherwise):

- **`${...}` placeholders**: copy each one exactly, character for character. You may move them
  to fit English word order. `"[${book.name}] 퀴즈로 복귀"` → `"Back to the [${book.name}] quiz"`.
- **HTML tags**: copy every tag exactly, including attributes (`<strong class="...">`, `</span>`, `<br>`).
  Same tags, same count. You may move them so the right words stay bold etc.

Rules the checker cannot see:

- Keep line breaks (`\n`) and list markers where they are: `①`, `1)`, `-`, `·`, `→`, `※`, `■`, emoji.
  One Korean line → one English line.
- **Slide-advance markers** `(넘김)`, `(넘기기)`, `(넘김 넘김)` → write `(next)`, `(next)`, `(next next)`.
- **Scripture references in angle brackets** like `<창 1:1>`, `<히10:23~25>` → `<Gen 1:1>`, `<Heb 10:23~25>`
  (abbreviations in the table below). Other references in running text: `창세기 1장 1절` → `Genesis 1:1`,
  `(렘 29:11)` → `(Jer 29:11)`.
- **File names and folder paths** (`H:\HDX\Church\...`, `*.mp3`, `*.pptx`, `*.hwp`): keep exactly as they are, Korean included.
- Dates: keep `B.C.` / `A.D.` **before** the number, exactly as in Korean, because code tests strings like
  `"B.C. 6"`: `B.C. 1446년경` → `c. B.C. 1446`, `A.D. 90년경` → `c. A.D. 90`.
- Words the code looks for inside other strings: `포로` → `Exile`, `귀환` → `Return`, `서신` → `Epistles`,
  `사무엘` → `Samuel`. Make sure longer texts that contain these ideas use the same English word
  (e.g. a date "B.C. 586 (포로기)" → "B.C. 586 (Exile)").
- Never leave a translation empty. A grammar-only piece (e.g. `개` in "목소리 N개") gets a short word that reads well when joined.
- `&` inside HTML files: write `&amp;`. In JS strings a plain `&` is fine.
- Short UI labels (buttons, tabs, badges) must stay short. `전체화면` → `Full screen`, not a sentence.
- Korean grammar endings glued to code (`${book.name}은`, `${n}장`) → write natural English
  (`${book.name} is`, `${n} chapters`).
- Use the glossary below **exactly** — some words are used by the code to match things
  (book names, categories, `전체` = `All`).
- Bible quotations: if you recognize the verse, use the wording of the **World English Bible** or
  the **King James Version** (both public domain). Do not copy NIV/ESV/NASB wording. Otherwise translate faithfully.
- Biblical names: standard English Bible spelling (느부갓네살 Nebuchadnezzar, 바로 Pharaoh, 애굽 Egypt,
  블레셋 Philistines, 고레스 Cyrus, 아하수에로 Ahasuerus). Korean modern names: given name + family name (김병희 → Byeong-hui Kim).
- If a Korean phrase is identical to its meaning in English already (e.g. `PPT`), just write the English.

### B. Whiteboard scripts (`pansuh/data/<id>-board.js` → `i18n/en/boards/<id>-board.js`)

The whiteboard player reads each beat's `say` aloud (English text-to-speech) while drawing the beat's `draw` ops
on a 1600 × 900 board in a handwriting font. See the top of `pansuh/assets/board.js` for what each op does.

- Copy the whole file, then translate. Keep **every** scene, beat, op, id, color, photo, and the order. Don't add or remove beats.
- Translate: the header comment, scene `title`s, every `say`, the text of `title` and `write` ops, photo `caption`s.
- `say` is spoken by a computer voice: natural spoken English, complete sentences, same content as the Korean.
  Avoid symbols the voice would read oddly (write "versus", not "vs."; "B.C." is fine; "chapter 3", not "ch. 3").
- **Board text must be short.** It is handwriting on a board: note style, no articles when not needed,
  symbols allowed (→ = ≠ +), abbreviations allowed (ch., v., OT, NT, Gen 1:1). English runs about 1.7 times wider than Korean
  for the same meaning, so aim for roughly the same visual length as the Korean.
- Layout: you may change a `write` op's `size` (not below 44), its position, and `gap` (also shrinking gaps
  between arrowed items) so English fits. Keep the Korean layout idea (what is under what, arrows, circles).
  Photos stay where they are unless text cannot fit otherwise. Rough feel: size 80 ≈ 30 px per English letter,
  size 56 ≈ 21 px, size 64 ≈ 24 px. Text near a photo on the right usually has room for only ~9 letters at size 80.
- Chapter ranges on the board: keep the Korean `~` style (`ch. 1~18`), consistently within a script.
- Keep paths in the header comment (`assets/board.js`) as they are.
- Check every file, from the `판서강좌` folder:
  `node tools/check_board.js --img ../bible/pansuh/img ../bible/i18n/en/boards/<id>-board.js`
  It must print `ok`. It reports text running off the board and overlapping items.
- Image paths stay `img/...` exactly as in the Korean file.
